# 학습 결과 요약 (2026-11-12)

[result_1110.md](result_1110.md) 이후의 v3(Day Token) 결과다. 브랜치 `feat/per-day-encoder`.
- v3_pm: v3_perday + 결측 Peer 가리기(`data.peer_missing_mask`), 5-fold

같은 기간 Hour Token(v5) 결과는 `per-hour` 브랜치의 `docs/result_1111.md`에 있다. 거기서 결측 Peer 가리기가 v5 fold 0 PR을 올려서(D128 T168: 0.548 → 0.588), v3에도 적용했다.

**공통 조건**
- Fold: `select_fold`, seed 42. 검증 건물 40개
- 평가: T=64일 고정 Window
- 지표: ROC-AUC / PR-AUC / F1(threshold 0.5) / 최고 F1
  - 최고 F1은 검증 정답으로 threshold를 고른 값이다. 비교용이다.
- Baseline: E0 LightGBM, 후처리 전(raw)
- best.pt는 F1@0.5로 고른다. 그래서 마지막 epoch 값도 같이 본다.

## 핵심 결론

1. **v3_pm 5-fold 평균: ROC 0.916 / PR 0.673 / F1 0.676 / 최고 F1 0.678.** v3 계열 최고다.
   - v3_perday 대비: ROC 0.000, PR +0.010, F1 +0.012, 최고 F1 +0.008 (best.pt 기준)
   - 마지막 epoch 기준 PR은 0.658 → 0.673 (+0.015)이다.
2. **개선은 대부분 fold 3에서 나왔다.**
   - fold 3: 마지막 epoch PR +0.080. 최적 threshold도 0.73 → 0.51로 정상 범위가 됐다.
   - fold 3을 빼면 나머지 4개 fold 평균 차이는 약 −0.001이다. fold 4는 −0.023이다.
   - 즉 "모든 fold에서 조금씩 좋다"가 아니라 "특정 fold에서 크게 좋고 나머지는 같다"이다.
3. **Day Token에서 효과가 Hour Token보다 작다.** fold 0 PR: v3 +0.002, v5 +0.040.
   - Hour Token은 같은 시각의 값 1개끼리 비교해서 0으로 채운 결측 Peer에 더 민감한 것으로 본다.
4. **Baseline과의 차이는 그대로다.** PR −0.09, ROC −0.045.

## 1. 변경 내용

- 옵션: `data.peer_missing_mask: true` ([dataset.py](../src/data/dataset.py), [train_supervised.py](../src/train/train_supervised.py))
  - Peer 건물의 하루 24시간이 모두 결측이면, 그 날짜 Token을 Attention Mask에서 뺀다.
  - 절반만 결측인 날은 가리지 않는다. 결측 시간은 기존처럼 0으로 채운다.
  - 대상 건물(그룹 열 0)은 결측이어도 가리지 않는다.
  - 기본값 false. 기존 config 결과는 바뀌지 않는다.
- 왜 필요한가:
  - 결측은 원래 단위에서 0으로 채운 뒤 log1p 표준화한다. 0은 −2.90이 되고, 이는 실제 0 사용량과 같은 값이다.
  - 기존 Mask는 그룹 크기 Padding만 가린다. 그래서 결측 Peer는 "그날 전기를 하나도 안 쓴 건물"로 Attention에 들어간다.
- 가려지는 양: train 결측 시간의 91%(114,959시간 중 104,040시간)가 하루 전체가 결측인 날에 있다.
  - 건물-날짜 73,200개 중 전체 결측 4,335개, 일부 결측 3,466개.
- 설정: `configs/v3_pm.yaml`. v3_perday에서 `peer_missing_mask`만 켰다.
- 테스트: `tests/test_peer_missing_mask.py` (결측 날짜만 가려지는지, 대상은 안 가려지는지, 가려진 값이 출력에 영향 없는지)
- 학습: 11-12 10:14 ~ 11:45 KST, fold당 약 18분 (T4)
