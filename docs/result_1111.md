# 학습 결과 요약 (2026-11-11)

[result_1110.md](result_1110.md) 이후의 결과다. 브랜치 `per-hour`.
- Hour Token(v5): Token = 건물 1개의 1시간 사용량 ([LEAD_HourLevel_Transformer_v5_Change.md](LEAD_HourLevel_Transformer_v5_Change.md))
- v5에서 Window 길이(T)와 모델 크기(D) 비교, fold 0
- 결측 Peer 가리기(`data.peer_missing_mask`), fold 0
- 학습량(epoch) 판단, 40 epoch 5-fold

**공통 조건**
- Fold: `select_fold`, seed 42. 검증 건물 40개
- 평가: v5는 T=168시간 고정 Window(T336 실험은 336시간). v3는 T=64일이다. 평가 Window가 달라 완전히 같은 조건은 아니다.
- 지표: ROC-AUC / PR-AUC / F1(threshold 0.5) / 최고 F1
  - 최고 F1은 검증 정답으로 threshold를 고른 값이다. 비교용이다.
- Baseline: E0 LightGBM, 후처리 전(raw)
- best.pt는 F1@0.5로 고른다(`metric_primary: f1`). 그래서 마지막 epoch 값도 같이 본다.

## 핵심 결론

1. **v5(Hour Token) 최종: 5-fold 평균 ROC 0.879 / PR 0.614 / F1 0.657 / 최고 F1 0.660.**
   - 설정: D 128, T 168, 결측 Peer 가리기, 40 epoch (`configs/v5_hour_pm_d128_e40.yaml`)
   - v3 대비: ROC −0.037, PR −0.049, F1 −0.007, 최고 F1 −0.010
   - F1은 v3와 거의 같아졌다. 순위 능력(ROC, PR)은 아직 v3보다 낮다.
2. **T(168→336)와 D(64→128)는 PR을 올리지 못했다.** fold 0 PR은 네 조합 모두 0.52~0.55다.
3. **결측 Peer 가리기는 효과가 있다.** fold 0, 4개 조합 중 3개에서 epoch 10~19 평균 PR이 +0.015~+0.031 올랐다.
   - 가장 좋은 조합(D 128, T 168)은 PR 0.548 → 0.588, F1 0.604 → 0.625다.
4. **학습량은 병목이 아니다.** 20 → 40 epoch에서 fold 0 PR은 0.588 → 0.590(best) / 0.592(last)다.
   - 5-fold 평균 PR은 epoch 24 무렵부터 0.61~0.615에서 멈춘다.
   - v5는 train loss가 epoch 2 이후 잘 내려가지 않는다(v3는 꾸준히 내려간다). 병목은 Token 표현(1시간 값 1개)으로 본다.

## 1. 데이터의 결측 구간

결측 = `meter_reading`이 NaN인 시간. 건물당 8,784시간.

| | train (200개 건물) | test (206개 건물) |
|---|---|---|
| 결측 비율 | 6.5% (114,959시간) | 5.7% (103,801시간) |
| 1주(168시간) 이상 결측이 있는 건물 | 58개 (29%) | 60개 (29%) |
| 1주 이상 결측 구간 수 / 시간 | 96개 / 96,516시간 (결측의 84%) | 100개 / 84,606시간 (82%) |
| 30일 이상 결측이 있는 건물 | 32개 | 31개 |

관측된 시간의 이상 비율(train):

| | 이상 비율 |
|---|---|
| 전체 | 0.023 |
| 긴 결측 구간(≥1주) 앞뒤 1주 이내 | 0.048 |
| 긴 결측이 있는 건물 58개 | 0.031 |
| 긴 결측이 없는 건물 142개 | 0.020 |
| 결측 시간 자체 | 0 |

- 결측은 대부분 긴 덩어리다. 긴 결측 주변에 이상이 2배 많다.
- 그래서 긴 결측이 있는 건물을 학습에서 지우는 것은 하지 않았다. 어려운 이상 사례를 잃는다.
- 결측 처리(기존): 원래 단위에서 0으로 채운 뒤 log1p 표준화한다. 0은 −2.90이 된다. 실제 0 사용량과 같은 값이고, 관측값 전체의 최솟값이다.
- 기존 Attention Mask는 그룹 크기 Padding만 가린다. 결측 Peer는 "사용량 0인 건물"로 Attention에 들어간다.

## 4. 학습량 판단 (`samples_per_epoch` 20000)

`samples_per_epoch`은 Window 개수다. Window 평균 길이가 달라서 같은 2만 개라도 보는 시간 수가 다르다.

| | step/epoch | epoch당 대상 건물-시간 | train 전체 대비 | 총 epoch | 총 학습량 (train 대비) |
|---|---|---|---|---|---|
| v3 (Day, T 1~64일) | 1,704 | 9.35M | 6.7배 | 10 | 67배 |
| v5 T168 | 1,271 | 1.13M | 0.8배 | 20 | 16배 |
| v5 T168, 40 epoch | 1,271 | 1.13M | 0.8배 | 40 | 32배 |
| v5 T336 | 1,268 | 2.25M | 1.6배 | 20 | 32배 |

- train 전체 = 160개 건물 × 8,784시간 = 1.41M시간.
- 20 epoch v5는 v3의 1/4만 봤다. 그래서 40 epoch로 확인했다(5절).
- 결과: 학습량을 2배로 늘려도 PR은 거의 그대로다(fold 0: 0.588 → 0.590). 학습량은 병목이 아니다.

## 6. 해석과 다음 단계

- Hour Token은 T, D, 학습량 어느 쪽으로 키워도 PR 0.61 근처에서 막힌다.
- v3(Day Token)는 Peer와 비교할 때 하루 24시간 모양 전체를 맞대어 본다. v5는 같은 시각의 값 1개끼리만 본다. PR 차이(0.663 대 0.614)의 가장 유력한 원인이다.
- 결측 Peer 가리기는 효과가 있었다. 다음 실험:
  1. v3(Day Token)에 결측 Peer 가리기 적용, 5-fold. Day Token은 하루 전체가 결측일 때만 가려지므로 효과가 더 작을 수 있다.
  2. Hour Token 입력에 그날 24시간 모양 정보를 함께 넣는 변형.
